## Explicit targeting and operations

Selection changes the target contract deliberately: an older eligible terminal session can be chosen even when a newer session exists. The latest session is no longer an automatic proxy or fallback. A new active/ambiguous latest session must not cause selection of an older one. This does not weaken the **current source** gate: every new calculation still requires healthy canonical storage, Connected/source active Idle, and acknowledgement of the latest received control in that same current epoch. Ordinary telemetry may remain pending. An older selected session may have its own different original epoch; retain both correctly.

A Calculate tap carries the selected UUID, not a row index or a deferred read of whichever row is current later. On the existing worker, re-read that session by UUID and validate OBSERVED_START/ENDED_LOCALLY/unambiguous, supported source/policy/acquisition and current control acknowledgement before beginning. Freeze R and the selected committed terminal snapshot through the existing calculation. If missing, changed, invalid or blocked, show an explicit reason; do not search backward, substitute latest or mutate the Collector checkpoint to make a historical session current.

Retain one coalesced action and at most one selected target/job/prepared completion. Disable selection/refresh/additional Calculate while analysis or an uncertain request/completion retry is active; show which session is being calculated. Do not cancel and retarget an uncertain write to another UUID. Before a job starts, selection supersession must discard an unstarted action for the previous target, never retarget its tap. Any new received Recording/Paused, source stop/loss or canonical retry/fatal state continues to cancel work through T04b3's sticky latch, including when the target is older. Canonical pump always runs first. Cancellation leaves the newest result honestly incomplete without an older-generation fallback.

A terminal success updates only the selected saved-result snapshot/row; no automatic calculation of other rows. Repeated Calculate for the same terminal input/config/code displays its acknowledged saved result without a duplicate run. Explicit Retry preserves T04b3 request/generation rules, and failed/abandoned newest remains authoritative. An unavailable duration inside a saved typed curve must not be confused with an unsaved failed analysis. New sessions do not silently change an explicit selection. If a refresh no longer includes the selected UUID within the 20-row cap, retain at most that one selected detail outside the list and mark it clearly; do not select another row automatically.

Saved past results can be read while a new ride is active, with Calculate disabled and current acquisition state displayed separately. This read-only view does not assert live numerical progress or whole-ride coverage. Selecting/refreshing/reopening never requests an analysis generation.

## Structure, bounds and storage

Reuse MainActivity/resources → DiagnosticRuntime → LiveCurveController → InputRepository/AnalysisRepository, all on the existing live input worker. No second Collector/source/worker/executor/measurement database or general history service. Existing SQLite sessions support a LIMIT 21 snapshot query and per-UUID lookup; existing analysis_slots/newest lookup provides status. SQLite rowid may order **recently persisted snapshots** internally: InputRepository currently uses INSERT OR REPLACE, so rowid is explicitly not session creation order, a durable identity or a pagination cursor. It never crosses the UI action boundary. Query order/truncation must be deterministic for a given committed database snapshot.

Load the bounded list and its revision in one short consistent read transaction on the worker. That list revision describes the row snapshot, not the later calculation freeze R; separately enriched result statuses reflect their own newest-slot read and must never override action-time revalidation. Retain at most 20 published cards, one transient lookahead snapshot and one selected detail; no whole-session/history list. Enrich at most one card's newest result per worker turn, pumping due canonical work before each turn. Refresh on initial runtime availability and explicit coalesced refresh, not Activity's twice-per-second render. Completion updates selected status directly; a dirty-list indicator can invite refresh after later canonical commits. Publish immutable bounded state; UI performs no SQL/numeric work. List/request failures remain explicit and retry only through existing bounded mechanisms or explicit refresh, without making acquisition success depend on a list read.

No database/schema/codec/model/parameter/hash/SDK or power-engine change is proposed. Keep real cohort, curve-body v3, exact five-second policy, frozen hash/replay and 32 MiB main-file cap on every live repository connection. Preserve existing preview slots/hash vectors, old codecs and zero curve aggregate membership. Same one-page ≤256-effect analysis cursor and work-v2 interval/work bounds apply. List work is bounded in retained rows and operations per turn, not a measured latency/RSS guarantee. Native SQLite internals and journal/temp overhead do not become a new hardware budget claim.
