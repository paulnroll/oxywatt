## E / A / S — Entities, approach and structure

No persisted derived values, aggregate membership writes, copied curves or new schema/store/core engine. Reuse existing result validation; factor only a minimal shared validator if necessary, with unchanged single-session behavior tests.

One HistoryController on the existing worker coalesces refresh/configuration commands. Begin after canonical work; enumerate once, resolve at most one session/newest-result entry per worker opportunity, yield to canonical ingestion between entries. At most 20 entries per refresh, with one cancellable refresh in progress and one coalesced replacement request. No raw observation replay or per-callback history scan. Each session/result read must validate exact identity/current generation before publication; sequentially gathered history is an explicitly bounded refresh snapshot, not a global atomic database snapshot. Invalidate/restart or suppress affected entries if newest authority changes; never claim atomicity from separate reads.
