# T03c — Transactional input batches and recovery

OWNER-APPROVED 2026-11-11 after merged PR #15. R03/R07/R10/R12; V04/V05/V09/V12 and input-storage portions of V14/V17. Dependencies: accepted T03a lifecycle and T03b admission; simulation-first amendment permits software work before T02 hardware acceptance. T03d/e/p remain excluded.

## Contract before code

Goal: durable canonical replay and conservative recovery without duplicate receipt keys or half-written checkpoints. Use Android platform SQLiteOpenHelper/SQLiteDatabase in `app/persistence`, no new dependency. Room was a conditional recommendation, not an accepted schema; platform SQLite supplies the small synchronous transaction boundary without an annotation processor. Keep Android outside core. Official contracts: [SQLiteOpenHelper](https://developer.android.com/reference/android/database/sqlite/SQLiteOpenHelper), [SQLiteDatabase](https://developer.android.com/reference/android/database/sqlite/SQLiteDatabase). Test real file-backed SQLite on Robolectric API 32/34, not a mock repository. Calls must run on an owner worker, never the UI thread; no live source wiring in this package.

`InputRepository.prepare(batch, lifecycle, expectedRevision, batchId)` computes T03a effects once and freezes a versioned encoded write. `commit(write)` atomically appends observations, lifecycle effects and loss/policy metadata, updates indexed session snapshots and the singleton checkpoint, and advances a database revision. Return committed revision; only then may the owner acknowledge T03b. Retain the same prepared write on failure, including an uncertain commit response. A retry of the same ID/content returns the original revision even after later commits; changed content under the same ID fails. A stale expected revision, receipt-key conflict or session UUID collision fails the entire transaction. Never silently ignore a conflicting input. Reject known batch IDs and overlapping committed receipt keys before any replay/lifecycle computation after restart; new epochs recover from the committed checkpoint rather than replay old transitions.

Tables v1: batches (UUID, digest, revision, versioned policy/loss/terminal metadata), observations (epoch/sequence unique globally, batch FK, optional session/segment, canonical source facts), effects (batch/index unique, full versioned lifecycle update), sessions (UUID and snapshot carrying the owning epoch), collector_state (singleton revision/checkpoint). Persist observations outside sessions too, including initial Idle/profile; every envelope-free effect remains durable. Bounded paged replay ordered by batch revision and input sequence; explicit lookup of committed batch and latest checkpoint/session. No whole-ride list API. JSON codec v1 explicitly names enum values and preserves nullable data, UTC nanoseconds, long sequences, profiles, policy/source versions and ambiguity. Unknown versions fail; no Java object serialization.

A transaction fault hook is internal test support only: throw after inputs/effects and before checkpoint/commit. SQLite-full exceptions propagate; admission is not acknowledged. Test actual SQL constraints and a real SQLite page ceiling in addition to injected stage failures. Reopen the file to verify atomic rollback, exact retry and crash-tail recovery. Database v1 is the first shipped schema: no fictional prior-schema migration; reopening v1 preserves data and unsupported upgrade/downgrade fails without destructive fallback. Future schema changes require explicit migrations and real prior-v1 fixtures (V14 remains partial until then).

Read/query failures and corrupt codec versions propagate, never fall back to empty history. A restarted Collector requires a new epoch and marks previous active sessions interrupted using T03a. Persist that envelope-free recovery together with the first new batch. Loss never becomes zero samples or a completed old session. No sensors, GPS, network, diagnostic raw logs, analysis results, UI, scheduler or hidden input queue.

Files: app persistence repository/codec and integration tests; architecture contracts, this task, Canvas/decision log/authorization references. Checks: focused behavioral red/green; opt-in Android tests, assembly/lint/dependency isolation; core check/build, formatting, Markdown/traceability, skill validation and diff checks. Risks: premature acknowledgement, retry replay, stale checkpoint overwrite, session UUID reuse, storage-full partial writes, unsafe destructive migration. Evidence must distinguish software transactions from device process survival.

Contract refinement: `prepareEffect` freezes one envelope-free timer/terminal/recovery update, with admission policy metadata, so silence and EOF need no fabricated observation. It shares the same revision/idempotency transaction. Read pages are capped at 256 records. Native double values use hexadecimal strings in codec v1 to retain negative zero and exact binary values. Database columns retain source facts; JSON storage overhead is distinct from T03b's domain payload charge and requires later N02 measurement.

Verified behaviors:

- Reopen a committed active checkpoint; exact input/profile/source/time/version round trips, including null missing reasons versus zero, negative zero, UTF-8 identifiers, FILE_RECORD provenance, UTC nanoseconds and long receipt keys above double's exact integer range through Long.MAX_VALUE. Paged input reads preserve order and optional session filtering; effect pages preserve envelope-free updates.
- Inject a failure after input/effect/session writes and before checkpoint; close and reopen the file, then retry the same frozen write. No partial inputs/effects/checkpoint survive, retry is idempotent and admission retains its budget until explicit acknowledgement. Retry an older committed write after later commits without moving the checkpoint backwards. Conflicting content under one batch UUID fails.
- Actual SQL receipt uniqueness rejects conflicting rows. Known committed IDs and receipt keys are checked before lifecycle application. Two independent repository instances racing at the same expected revision produce exactly one committed writer; stale/conflicting writes cannot replace state.
- Restart in a new epoch interrupts the durable prior session and creates a separate linked ambiguous fragment, retaining original profile provenance. Missing recovery effects and reused session UUIDs fail atomically. Standalone silence and source-stop effects persist without manufacturing observations. Control exhaustion and a loss-only batch persist loss metadata and interruption without completing the previous session.
- A real 64 KiB SQLite page ceiling causes SQLITE_FULL during a 501-input batch. No rows/effects/checkpoint survive; the admission count remains 501. Raising the ceiling permits the exact same frozen write to commit and the file reopens at its committed revision. SQLite automatically rolls back on full storage; preserve the original SQLiteFullException and attach any endTransaction cleanup failure as suppressed, rather than hiding the storage reason.
- Reopen schema v1 without modification; future schema downgrade is rejected while original rows remain. Unsupported checkpoint codec versions fail explicitly without empty-history fallback. There is no pre-v1 production input database to migrate; real v1 upgrade testing is required when the schema next changes.
