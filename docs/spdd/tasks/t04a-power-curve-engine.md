# T04a — Simulation-backed observed power-duration engine

Status: specification prepared on 2026-11-11 following the owner's request to continue without a bicycle and postpone live tests until the end. **Owner approved T04a implementation after PR #21 merged on 2026-11-11.** This proposed dependency amendment permits the pure numerical engine before T03e; T04b/device integration and parent T04 acceptance retain their live gates.

## Goal and scope

Deliver a source-neutral Kotlin/JVM engine for observed time-weighted power maxima at 5/30/60/180/300/600/1200/1800/3600 seconds. R04/R07/R11; V06/V09 and software-only V13/V18/V19/V22. Consume explicitly covered power intervals, not aligned samples or SDK objects. Missing duration is unavailable; zero is a valid result. No FTP/CP/VO2max estimate, history, Android UI, database schema, live source or release change.

Dependencies: T01 canonical timing/simulator contracts, T03a session/coverage semantics, accepted [power calculation](../../algorithms/power-curve.md), [ADR 0002](../../architecture/adr/0002-independent-estimators.md). T03b–d are available for later consumers but are not runtime dependencies of a numerical core. T03e and full T02c remain deferred; a passing simulator cannot accept their hardware claims.

## Input, time and coverage contract

The minimal public boundary accepts immutable, confirmed piecewise-constant intervals with session ID, acquisition epoch, recording-segment identity, start/end elapsed nanoseconds and finite nonnegative watts. Use half-open [start,end) intervals and positive durations. Reject overlaps, time regression, invalid values or mixed identity inside a contiguous segment. Do not use UTC or FILE_RECORD audit timestamps for receipt-domain durations. Never infer that two different UUIDs are the same ride.

Intervals must represent coverage already confirmed by a caller. **T04a does not convert the latest reading into unlimited future power.** A later adapter must close a held value at the earliest next power reading, missing event, configured expiry, pause, interruption or known end. Until that adapter exists, only independently specified synthetic interval tables feed this engine. Do not claim an end-to-end canonical-input or persisted-ride curve from this package.

Adjacent intervals with the same session/epoch/segment are continuous; a positive time gap breaks all windows. An explicit break, even at an adjacent timestamp, also prevents joining windows. Start of a new recording segment/epoch/session resets rolling coverage. Retain already observed per-duration winners for the current session across ordinary pauses/gaps, but never bridge them. A new session gets a new curve. Partial/interrupted-session results remain partial observations, not eligible historical trend contributors. HR/cadence absence does not invalidate explicit power coverage.

A window ending exactly at a break can qualify using fully covered time before the break. No right-hand value is extrapolated beyond the last confirmed interval. Equal adjacent timestamps contribute no duplicated duration. Numerical integration uses fractional interval boundaries at nanosecond resolution, with elapsed differences calculated safely before conversion to seconds.

## Output and numerical policy

Each duration returns either unavailable with a bounded reason (insufficient contiguous coverage or resource limit), or the best observed mean watts and exact [start,end), session/epoch/segment provenance. Include preprocessing/configuration versions and coverage origin supplied by the caller. Deterministic ties select the earliest start within the same session; compare input-order-independent equal candidates without a user-facing confidence claim. Existing winners remain valid observations after a later coverage break; output must distinguish a resource-limited scan from a complete scan.

Use exact piecewise-constant integration rather than sampling a regular grid. A complete maximum search includes window endpoints at interval boundaries and those boundaries shifted by the target duration; between such endpoints the rolling energy is linear. Clip to the actual covered domain. Candidate enumeration must include expiration-side boundaries, not merely input arrival times. Tests must derive expectations independently rather than snapshot production output. Numerical test tolerance is max(1e-8 W absolute, 1e-12 times the expected magnitude); timestamps and selected windows remain exact integers. Reject nonfinite arithmetic outcomes explicitly without corrupting trusted state.

Retained state is bounded by the largest requested duration and a versioned hard interval cap. Proposed `power-intervals-v1`: retain at most 16384 interval fragments (including any partial boundary fragment), plus at most one winner per duration; caller can select a smaller positive cap in tests. Evict history older than needed for 3600-second windows. Coalesce exactly adjacent equal-power intervals only within the same uninterrupted identity. If the cap would be exceeded, preserve established winners, report resource-limited coverage, break the affected rolling stream and release its interval buffer before admitting a new independent span. Never silently discard a middle interval and then bridge it. This is an engineering limit, not a physiological threshold or measured device memory budget. Test repeated saturation and document operation counts/retained-state plateau; no four-hour battery/RSS claim.

## Approved implementation contract refinements

One engine instance belongs to one session; a different session requires a new instance. Intervals carry epoch/segment identity. Identity changes break coverage automatically; a decreasing segment or overlapping/regressing time within the same epoch is rejected. An epoch change permits its new monotonic origin. Explicit breaks release rolling state while retaining the last accepted stamp for same-epoch order validation. Rejection leaves the complete engine state unchanged and a corrected interval can be retried.

Equal maxima within the declared numerical tolerance select the earliest start; across different epochs (incomparable monotonic origins), retain the first encountered tied winner. Output retains resource-limited status even when an established numeric winner exists. The positive interval cap is enforced before retaining an additional unequal interval; saturation restarts coverage at that incoming interval, preserving winners. Energy is integrated as weighted watts with compensated summation, avoiding a growing absolute-energy prefix and its cancellation/overflow. Counters expose evaluated windows and integrated fragments for software cost evidence; they do not measure device resources.


## Executed software evidence — 2026-11-11

T04a is implemented in `core/power/PowerCurve.kt`, with three numerical anchor cases in PowerCurveTest and eleven acceptance cases in PowerCurveAcceptanceTest. No dependencies, Android/runtime wiring, interval builder, storage schema or physiological model changed. The owner approved this package after PR #21 merged.

The engine consumes explicit immutable coverage intervals, belongs to one session, and publishes versioned provenance/policy, exact winning boundaries/identity, unavailable reasons and whole-scan resource status. It does not infer recording completeness or history eligibility; future consumers must combine observations with actual session metadata. Equal adjacent intervals coalesce. Windows use compensated weighted watts rather than cumulative energy subtraction; candidate search includes expiration-side boundaries. Same-epoch order/segment validation and all numerical evaluation precede state publication, so a rejected input can be corrected and retried.

TDD: the compiling empty engine failed the constant covered-power assertion, then passed after minimal single-interval support. The ramp/zero and fractional interior-optimum tests failed before multi-interval integration and expiration-boundary enumeration. Self-review reproduced a mutable public duration list: the added behavioral test failed before wrapping the shared list as unmodifiable. A second self-review regression failed because callers could clear snapshot durations; wrapping the independently published list made that immutability assertion pass, and an earlier snapshot remains unchanged after later ingestion. Other acceptance cases were added against the integrated implementation and are not claimed as individually observed red tests.

Independent evidence includes the 300 s/200 W and five-second ramp anchors; the fractional table 0 W over [0,1.5), 100 W over [1.5,3.5), and 50 W over [3.5,7.5) has its best five seconds at [1.5,6.5), exactly 70 W. Six fixed-seed irregular traces agree with a separate integer quarter-second-cell energy oracle, including every required duration in the 4000-second trace. This grid oracle is exact for the selected test intervals and is not the production candidate algorithm. 1x/10x/unpaced virtual delivery clocks produce equal acquisition-domain snapshots without sleeps. Explicit gaps/adjacent breaks/segments/epochs do not concatenate short spans; original winners survive gaps. Invalid inputs leave snapshots unchanged, including same-epoch regression after a break. Exact endpoints, deterministic ties, near-Long.MAX_VALUE timestamps and finite 1e308 W inputs pass.

Four simulated hours of alternating 100/200 W at 1 Hz evaluated 243659 candidate windows and integrated 187673925 overlapping fragments. Retained intervals plateau at 3600; all nine durations have numeric records without saturation. Repeated saturation with a cap of two retains at most two fragments, preserves the earlier numeric winner and reports RESOURCE_LIMIT for unfilled durations plus resourceLimited=true for the whole scan. A cap-one equal-power run coalesces without false saturation. These are structural/operation-count software checks, not measured device RSS/battery/residency. Direct overlap integration trades additional CPU for numerical stability; worst-case work for one long incoming interval after many short intervals can be quadratic in retained interval count per duration. No real-time high-rate CPU budget is claimed; T04b integration must review that workload before live use.
