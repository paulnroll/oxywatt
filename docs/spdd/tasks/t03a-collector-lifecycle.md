## Contract and policy

`CollectorLifecycle` consumes `SourceObservation` before persistence, assigns local session IDs and emits a bounded `LifecycleUpdate`: optional canonical envelope and recording segment index, at most two changed session snapshots (recovered previous session plus current), at most three channel coverage breaks, rejection reason and an immutable checkpoint. Consumers must process session/coverage/checkpoint effects even when no input envelope is emitted, including rejection and terminal updates. There is no retained event/session list or callback queue. Calls are serialized by the owner; this state machine creates no threads/timers. `accept`, `advanceTime`, `interrupt` and `sourceStopped` return effects rather than invoking application callbacks.

Construction names the acquisition epoch and a versioned `LifecyclePolicy` with an explicit positive channel-silence timeout in nanoseconds. This is an engineering coverage policy, not a physiological threshold; no universal default is selected. The driver advances this same monotonic acquisition clock during silence, using V18 timer-before-input ordering. UTC/source times never establish duration. Each input must match the epoch, have increasing local ingest sequence and nonregressing monotonic time, including explicit clock advances. Changing adapter identity/version or normalization version inside an active session is rejected rather than silently merging input sources. Invalid order/epoch interrupts active acquisition and rejects the offending envelope. A committed replay is deduplicated by T03c before applying new lifecycle transitions; T03a does not implement database idempotency.

Only an observed Idle → Recording from the same adapter/version and normalization policy creates an observed-start session. Initial/repeated Idle and out-of-session metrics do not create completed rides. Attachment in Recording or Paused starts a partial cold/linked recovery fragment; resume retains its partial status. Pause breaks all acquired channel coverage; resume starts a new segment in the same session. Repeated Recording/Paused do not split sessions/segments. Idle ends only an active session locally, including its final envelope; it never asserts native save/discard. Subsequent Idle → Recording creates a distinct session.

Session snapshots retain origin, epoch, locally observed first/last receipt, segment, policy and optional ambiguity group. `trendEligible` is a structural prerequisite only: ended locally, observed start and no ambiguity. It is not physiological/model eligibility. Source stop/EOF/cancellation/error while active marks Interrupted, even if paused, and resets trusted host state. Explicit unknown state, transport loss or control-capacity failure also interrupts; no fabricated Idle or merge. A later active state creates a new linked ambiguous fragment until a fresh observed Idle → Recording boundary establishes independence. Ordinary channel gaps do not make session identity ambiguous.

Per-channel coverage tracks at most power/HR/cadence. Present values, including zero power/cadence, are unchanged. Explicit missing values emit a channel break; silence emits one break at `last channel receipt + timeout`, once until a new present value. Other channels/profile/control callbacks cannot hide channel silence. Only previously acquired channels need a silence break. Resume clears prior channel continuity; metric inputs while paused remain persisted but have no recording segment. No aligned RideSample, interpolation or power calculation is implemented.

Checkpoints carry schema/policy versions, epoch, last accepted receipt, latest session and the latest profile observation with original provenance. On construction from a checkpoint, require a new epoch: no previous Idle/Recording state proves current continuity. An active prior session becomes Interrupted/PROCESS_RESTART; the first transition returns that change so a repository can commit it with the new checkpoint. A new active observation receives a new UUID and common ambiguity group. Repeated restarts keep the group, never reopen a prior UUID. Profile context is retained without inventing a new receipt/effective time or replaying a synthetic profile envelope. Checkpoint values are not claimed durable until T03c commits them.
