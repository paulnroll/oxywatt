## Investigation and alternatives

[Reproducible baseline cost evidence](../../evidence/t04b2-cost-2026-11-11/README.md) separates actual T04a counters from wrapper reservations. Current T04a successfully scans four hours of alternating 1 Hz power: 243659 candidate windows, 187673925 overlapping fragments, 3600 retained intervals. Current wrapper accepts only 186 intervals (19773567 reserved units), so its limit is not a measurement of that engine scan. Irregular nanosecond intervals require 268823 windows/188198516 fragments; explicit breaks reduce work but do not repair the wrapper's accumulated reservation. Dense 1 ms input followed by a confirmed one-hour interval demonstrates many expiration candidates in a single append, each reintegrating retained history.

| Alternative | Benefit | Decision |
|---|---|---|
| Increase 20M or remove budget | Tiny edit | Reject: quadratic dense-then-long append remains; no bounded inner work/cancellation guarantee |
| Precisely charge direct integration | Removes reservation pessimism, preserves numerical path | Insufficient alone: representative 1 Hz already consumes 187M fragments; dense retained input still quadratic per append |
| Rolling energy/prefix subtraction | Small fast query | Reject for this package: subtracting large nearly equal totals and cumulative drift require separate numerical evidence; finite extreme watts can overflow energy |
| Balanced bounded interval aggregates, local weighted means | Logarithmic range queries without growing-energy subtraction | Select: reuse candidate enumeration, coverage semantics and persistence; one bounded internal index |

## Approach and numerical contract

Keep exact half-open nanosecond intervals, all nine durations and arrival plus expiration-side boundary candidates. Enumerate candidates in the existing chronological order; deduplicate integer endpoints as today. Include minimum eligible end, incoming end and every retained start shifted by duration within the confirmed domain. Do not prune candidates based on power or approximate time grids. Process expiration candidates before evicting their required history, especially for a long incoming interval. Input spans are confirmed coverage, never permission to extend hold beyond persisted expiry.

Replace repeated fragment scans with a balanced range index over the same coalesced retained intervals. A node summarizes its exact covered integer duration and a duration-weighted mean, not a session-energy prefix. Query a window by combining disjoint fully covered nodes plus at most two clipped boundary leaves and the incoming interval. Use local duration ratios and compensated additions in deterministic chronological order. Avoid overflow-prone watts×nanoseconds and large-total subtraction. Keep equal-power coalescing, clipping, gap/identity resets and 16384-fragment hard cap. The index is internal to the existing engine, not another source of coverage truth.

Mathematical basis: within a contiguous piecewise-constant span, rolling energy is linear between arrival/expiration boundaries, so this retains the complete candidate set. A disjoint range decomposition computes the same weighted mean without visiting every covered leaf. Floating-point regrouping still needs independent validation; this proposal is not executed numerical evidence. Preserve tolerance max(1e-8 W absolute, 1e-12 × expected magnitude), exact winning integer boundaries and existing tolerance-based earliest-start ties within an epoch; retain first encountered tied winner across epochs. In adversarial near-ties require the same contract against high-precision expectations, not merely agreement between two Double algorithms. If the selected aggregation cannot meet these criteria, do not relax tolerance or ship; revise the proposal before expanding implementation.

Rejection remains retryable and leaves trusted numerical state unchanged. Validate and calculate before publishing the new interval/winners. A work-limit exit may publish only already fully evaluated candidate observations, explicitly incomplete; never a half-integrated candidate. No approximate maximum or silent resampling.

## Operations, memory and reproducibility

Introduce versioned `power-range-means-v2` model/policy and `power-replay-work-v2` engineering policy. Retain `canonical-power-hold-v1`, receipt/expiry/lifecycle ordering and coverage origin unchanged. Charge one unit for each index node visited, aggregate merge/weighted contribution, candidate evaluation and interval/index mutation; count candidate enumeration and eviction visits too, including failed/reserved operations. Specify counters in code comments and tests; no uncharged loop over retained history. These units differ from v1 reservations and must never be presented as comparable CPU measurements.

Proposed hard total budget: 100000000 units per calculation. Charge/check before each bounded operation, including within an append; cancellation checks at least every 1024 units and each replay page. Use checked/saturating counters; exhaustion cannot overflow back to available budget. This is an engineering cap coupled to the improved algorithm, not simply a larger allowance for direct integration and not a Karoo timing budget.

For N emitted intervals, K enumerated candidates and cap C, require O((N+K) log(C+1)) index work, including inserts/evictions; no O(K×C) integration. At fixed nine durations, each boundary creates at most one expiration event per duration plus append endpoints. Assert ≤100M charged units for every acceptance fixture, with actual counts reported separately by category. Also run doubled-length fixtures at the same density and require ≤2.5× units after accounting for warmup. Record elapsed JVM time as descriptive evidence with runtime/machine, never a fragile wall-clock test or device claim.

Retain ≤16384 interval leaves, ≤16383 internal aggregate nodes, ≤9 winners and a candidate buffer ≤C+3 for one duration. Include any transactional staging: total live tree nodes ≤4C+2 and total candidate storage ≤C+3; no whole-session interval/result list, unbounded event heap or old tree snapshots. Replay remains paged (existing 256-row default); manifests/oracles may be test-only arrays. Instrument retained/staged high-water marks across repeated four-hour runs. Resource saturation preserves established observations, breaks affected coverage and latches incomplete search as today; work exhaustion stops numerical admission and releases scratch state while replay can finish metadata/hash processing. Distinguish insufficient coverage, memory saturation, work limit, cancellation and invalid input using existing snapshot/work flags and bounded terminal reasons. Do not label a numeric winner a complete maximum when search was incomplete. Cancellation/invalid input remains a FAILED newest generation, with no fallback.

Use the existing semantic hash, provenance, slot selection and typed curve-v2 terminal. Include new algorithm/work versions, cap and budget in the hash/configuration. Keep the existing logical slot (whose legacy label includes budget-v1) so new requests supersede old generations; policy meaning comes from versioned provenance, not that opaque slot label. Do not introduce a parallel slot that could expose a stale winner. Keep scalar-v1 and old curve-v2 readable; no reinterpretation of old reservedWork. New work-v2 provenance identifies charged units in the existing work field. Display current newest generation with incomplete status through existing readout; update wording only if needed, in English resources. Preserve atomic nine-result writes, exact retry, no-fallback and synthetic aggregate exclusion.
