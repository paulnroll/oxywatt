## Bounded execution and owner participation

Approved scope: **one** stationary native recording, approximately 45–90 seconds of state holds, within a maximum ten-minute device/evidence window. The owner operates all native ride controls. The agent may inspect the existing diagnostic UI, selected app-only logs/report and private canonical database copies through USB after approval. Keep USB attached and screen awake; return briefly to native ride controls as needed, then to diagnostics. This is not a hidden/no-field or screen-off test. No sensor is required: zero power/cadence and unavailable HR are acceptable. Do not change auto-pause/profile/pairing settings; if auto-pause prevents the specified manual sequence, stop with partial evidence and propose a separate adjustment.

1. **Baseline (agent):** confirm correct package/hash and Connected/Idle with healthy canonical storage. Preserve a consistent private baseline database snapshot, its revision r0, session/analysis counts, current epoch, report/source markers and UI counters. Confirm the actual persisted Idle in this epoch before asking the owner to start. If a session is already active, storage is blocked, the build differs, or baseline cannot be captured, do not start this trial.
2. **Start (owner):** press native Start once while stationary. **Agent:** verify actual RECORDING callback, then committed local RECORDING session; hold about 15 seconds after callback receipt. Screenshot the diagnostic counters/session/status. A button press alone is not a callback oracle.
3. **Pause (owner):** press manual Pause once. **Agent:** confirm PAUSED callback and committed PAUSED for the same local session; hold about 10 seconds, exceeding the five-second engineering timer. Capture counters/status. Paused metrics may continue to arrive and persist without recording segments.
4. **Resume (owner):** press Resume once. **Agent:** confirm RECORDING callback and committed same session with segment index 1; hold about 15 seconds. Capture counters/status. Repeated equal host states must not add segments.
5. **End (owner):** use native end control and handle any native save/discard confirmation personally, choosing discard for this test if desired. If this introduces an additional PAUSED state, retain it in the actual trace; do not suppress or fabricate the ideal trace. **Agent:** require observed IDLE and committed ENDED_LOCALLY. Idle is a local end only; neither it nor FIT cancellation proves native save. No FIT export/read-back is part of this package.
6. **Drain observation (agent):** allow at least one five-second flush interval, then capture a diagnostic snapshot with committed revision r and the matching database prefix plus a later consistent snapshot containing the final Idle. Read copies after reopening them locally to verify retained rows/checkpoint. Do not stop the service or require pending=0: callbacks continue after Idle. Spend at most 30 seconds per transition/commit confirmation and at most three snapshot attempts; on failure retain partial evidence, do not repeat the ride automatically.

If any step fails or a disconnect/epoch change occurs, stop advancing the planned sequence. The owner ends any active native recording; collect the available tail without teardown, forced retry, process kill or extra ride. An unintended extra transition is evidence, not grounds to silently pass the planned trace. A final native Pause before Idle is allowed if documented; auto-pause, unknown state, transport loss or loss counters make the clean-sequence result partial.
