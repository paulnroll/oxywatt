## User-visible behavior

Register one graphical type, **OxyWatt · Saved power curve**, under the existing extension. It is explicitly historical: field header **Saved power · 5 min** (duration substituted), large watts with W, and a footer **Session · 12 Nov 2026** using the session's first local receipt UTC date. Details in the app identify this as a receipt date, not native workout creation/save time. No “today”, fitness delta, FTP, VO2max, distance or live progress claim.

In the existing app's local-session controls, add **Use saved curve in ride field**, a nine-duration selector (5 s, 30 s, 1 min, 3 min, 5 min, 10 min, 20 min, 30 min, 60 min), and Light/Dark appearance. Default duration is 5 min, default appearance Light. The explicit action binds the currently selected supported saved real-provenance session; selecting another diagnostic row alone does not retarget the field. Show the bound session/date/duration independently, with a Clear action. No Calculate, Retry or source start is triggered by binding, clearing, displaying or reopening the field. App strings remain English resources.

Persist only a versioned small preference record: session UUID, selected duration and appearance. Never copy the numeric curve or store row indices. Update the record as one complete value; corrupt/unknown versions produce an explicit setup error. A fresh process restores the binding, then validates and loads the current authoritative result through the existing worker before displaying numbers. Until then show Loading; never flash a previous process's cached curve. Binding is separate from T04b4's intentionally runtime-only diagnostic selection.

At bind time validate the selected UUID and newest real result; only a supported saved typed curve can be bound, including a curve with unavailable durations. Keep that UUID fixed: never choose another session automatically when it is deleted, falls outside the 20-row list, or its newest result becomes pending/failed/unavailable. Read exact UUID, not list rank. In those states show the reason and no older-generation numeric fallback. Treat real slot/session/acquisition/codec mismatches as errors. Clearing binding returns to setup state.

The field remains read-only during recording. Attaching/hiding/detaching a field never controls collection, creates a source/Collector/database, requests analysis, or extends service residency. Use the existing service-owned worker and repositories only. If that worker is unavailable, show **Open OxyWatt** / **History unavailable** rather than opening storage from a view or promising independent background history access. Existing source lifecycle remains unchanged and conditional.

## Visual contract

- Large field: strong tabular numeric hierarchy, restrained teal accent, compact log-duration power curve, visible saved-session header/footer. Dark and Light are explicit app choices; do not infer an automatic host theme API from the mockup. The cached SDK ViewConfig has no theme property.
- Compact field: retain duration, watts/unit and saved-session date; omit chart before sacrificing those labels. Very small configurations show an explicit **Enlarge field** state if provenance and value cannot fit. Actual thresholds are determined by host dimensions/text settings and verified with SDK fakes and hardware, not invented grid sizes.
- Use exactly the existing nine supported durations. Horizontal position is log(duration); watts use a linear scale with a zero baseline, no smoothing or extrapolation. Selected available duration has a marker. Connect only adjacent available duration entries; missing/resource-limited values are absent points and break the line. Never bridge a missing point or substitute zero. A valid 0 W is rendered at zero.
- Main value is the stored duration result, rounded only for display to whole watts with locale-stable formatting; never derive it from the drawn line. Selected unavailable duration shows an em dash and **No covered window** or the stored resource-limit reason. Other valid points can remain visible. Resource-limited curves also carry a visible **Limited scan** label; never silently present a partial scan as a whole-session maximum.
- Empty setup: **Choose a saved session in OxyWatt**. Loading, no covered window, deleted session, pending/failed result, unsupported provenance, unavailable worker and read/storage error have distinct text. Read errors replace numeric output; no stale success presented as current. Text and marker shape carry meaning without color.
- No interactions are required on the ride page. Configure duration/session/appearance in the app, with a live synthetic design preview optional only if achievable inside this slice's existing UI ownership. No new Compose/navigation framework.

## Architecture, bounds and collaboration boundary

App configuration → small versioned preferences → existing worker's exact-UUID/newest-result read → immutable field snapshot → SDK DataTypeImpl.startView / RemoteViews. Registration must follow actual pinned SDK XML/types conventions. No SDK upgrade, new permission, module, dependency, schema migration, alternate result store or core change is proposed. Chart bitmap drawing is app-side presentation, not another analytical engine.

The worker services at most one coalesced field reload after canonical work: at binding/start, bound-result completion and a bounded stale-check no more often than once per five seconds while a field is subscribed. One exact session/current-slot/typed-result read sequence, no metric replay or history scan. Revalidate UUID/current generation consistently; if repository methods cannot obtain a coherent result without a small read transaction, propose the minimal read-only query at the shared boundary before implementation. During idle polling unchanged snapshots cause no rendering emission. No unconditional per-frame redraw.

Retain one binding and one immutable nine-duration snapshot; field emitters use cancellable subscriptions with no uncancelled jobs. Bound chart output to at most 512 × 512 ARGB pixels per attached view (approximately 1 MiB pixel data), coalesce updates to at most once/second per view and render only changed content/configuration. Cancellation releases the view's scheduled work/bitmap references. Host controls field instance count; this is a per-view engineering bound, not a process RSS/battery claim. An oversized host view scales the bounded bitmap; tiny views use the explicit fallback.

The separate storage session owns cap/retention/recovery policies, migrations and related tests. This slice owns new field renderer/configuration/presentation tests and the smallest registration/runtime hooks. Do not edit storage remediation files or switch the shared checkout. Before implementation, reconcile the actual merged baseline or use a separately authorized isolated checkout; shared Activity/runtime/build/docs edits require coordination. No cleanup, cap change, deletion, private input read, recording or install is part of this proposal.
